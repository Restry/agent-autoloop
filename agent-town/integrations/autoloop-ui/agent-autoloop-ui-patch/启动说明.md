# Agent 小镇接入 Agent Autoloop：启动说明

## 1. 文件清单

| 文件 | 用途 |
|---|---|
| `agent-town-autoloop.html` | 小镇页面，单个文件，双击打开 |
| `ui.patch` | 中台源码补丁（4 个文件，全部在 `host/` 目录） |
| `host/ui.ts` | 新增文件：跨域处理、规则文件读写接口 |
| `host/server.ts`、`host/http.ts`、`host/config.ts` | 改动后的完整文件，可直接覆盖 |

## 2. 给中台打补丁

中台程序目录默认是 `~/.agent-autoloop/app`（Windows 是 `%USERPROFILE%\.agent-autoloop\app`）。

方法 A（用 git）：

```
cd ~/.agent-autoloop/app
git apply /路径/ui.patch
```

方法 B（直接覆盖）：把本压缩包 `host/` 里的 4 个文件复制到中台的 `host/` 目录。

补丁基于你提供的 `agent-autoloop-main.zip`。中台执行 `agent-autoloop update` 后，需要重新打补丁。

## 3. 修改中台配置

打开 `~/.agent-autoloop/config.json`，在 `hub` 里增加 `ui`：

```json
"hub": {
  "listen": "127.0.0.1:3350",
  "publicUrl": "http://127.0.0.1:3350",
  "ui": { "origins": ["null"] }
}
```

- `"null"` 代表“双击打开的本地 HTML 文件”。
- 页面放在网站上时，把网站来源加进去，例如 `"https://town.example.com"`。
- `origins` 不写或为空时，跨域访问保持关闭，中台行为与原版相同。

修改后重启中台（`agent-autoloop up`，或重启后台服务）。

## 4. 取得本人密钥

`config.json` 里的 `owner` 字段是安装时生成的本人密钥。也可以新建一把：

```
agent-autoloop key new owner town
```

## 5. 打开小镇

1. 双击 `agent-town-autoloop.html`（需要联网加载 Three.js）。
2. 选择“连接中台”，填写地址 `http://127.0.0.1:3350` 和本人密钥。
3. 密钥只保存在当前页面会话，关闭页面后清除；点击右上角“退出”也会清除。

另外两个入口：

- 导入快照：粘贴 `agent-autoloop status --json` 的输出，只读，不需要打补丁。
- 演示：浏览器内的模拟数据，画面带“演示”标记，不需要中台。

## 6. 补丁增加的接口

| 接口 | 作用 | 条件 |
|---|---|---|
| `OPTIONS *` 预检、跨域响应头 | 允许 `hub.ui.origins` 里的来源访问 | 来源在名单内 |
| `GET /v1/rules-file` | 读取 `rules.json` 全文 | 本人密钥；默认只接受本机 |
| `POST /v1/rules-file/check` | 检查一份规则文本，不保存 | 同上 |
| `PUT /v1/rules-file` | 检查通过后保存，上一版备份为 `rules.json.bak` | 同上 |

- 规则读写接口默认只接受本机直连的请求；经过反向代理的请求（带 `X-Forwarded-For` 等头）会被拒绝。
- 以后中台上云、需要远程改规则时，在 `hub.ui` 里加 `"remoteRules": true`。这会让持有本人密钥的远程请求可以改规则，请先评估风险。
- 原版设计是“规则只由本机文件决定”，这个补丁改变了这一点。

## 7. 画面与中台的对应关系

| 画面 | 中台数据 |
|---|---|
| 来源站（入口道路两侧） | `sources`，数字是累计事件数 |
| 院落 | 规则的分组（`group`），同组规则排同一条队 |
| 院内小屋 | 一条规则；屋顶颜色是它交给的 Agent；最多画 6 间，其余在列表里 |
| 小屋门口的包裹 | 排队中的轮次（`queued`） |
| 传送带上和工作台上的包裹 | 已被领取的轮次（`claimed`、`unknown`） |
| 中台 | 内核；点击查看总数 |
| 工作站 | `agents`；所在电脑离线时熄灯 |
| “电脑 · 名称”标签 | 干活的电脑（`worker`） |
| 信箱楼 | `channels` |
| 复查闹钟 | `timers` |
| 无主货场 | `unrouted`（没有规则接的事件） |
| 院内堆放的箱子 | 规则暂停期间跳过的事件 |
| 小棚 | `elsewhere`（别处定时任务） |

## 8. 已知限制

- 规则、Agent、来源、通道的配置变化后，页面会自动重新加载来重建小镇。
- 中台不提供 Agent 干活的中间步骤，包裹在工作台上停留的时间等于这一轮真实的运行时间。
- 页面打开前已经结束的轮次不生成包裹，可在“轮次记录”里查看。
