# 任务进度与授权续办展示

任务记录以确认卡的事实关联归组：读取既有只读 why API，用 run_events.event_id → cards.answer_event → cards.run_id 找到续办所属的初始任务。不会按规则名称、日期或共享会话猜测关联；独立定时触发保留独立任务。历史缺失会标明，读取失败不会误报归属。

原始轮次保留在任务详情中，仍可查看回执、错误、成果和原有操作。任务列表、Agent 工作站、院落计数及活动条使用统一任务分组；排队的授权续办不另显示成一个待处理任务或额外排队包裹。

引擎的 done 只代表本轮结束。展示层优先显示尚未回答的阻塞卡、执行/排队的续办和不确定状态。阻塞回执显示阻塞；同步只有明确完成回报、已读取对应卡片证据且无未结束续办/开放阻塞卡时才显示完成；其它情况显示完成待确认。该状态依据 Agent 回报，不是独立的业务验收器，不替用户断言代码或数据库验证通过。失败、未知和停止分别保留。

原始轮次结束计数标成“已结束轮次”；近期完成任务只统计当前已加载记录。阻塞或待续办的轮次不会播放任务完成庆祝。

验证：task-progress.test.mjs 覆盖两张卡片合并、不同日任务隔离、待续办阻止完成、开放阻塞卡、缺失历史、否定/将来时回报、证据尚未加载和分页后的多级续办。与原有 task-alerts 测试共 8 项通过。浏览器确认第 171 轮及 172/173/174 的续办在同一任务中展示。

部署：只原子替换常驻网页运行目录的 task-progress.js、index.html 和 agent-town-autoloop.html。未重启网页服务或中台，未修改规则、任务、确认卡或业务代码。中台 worker PID 在更新前后均为 9310。
