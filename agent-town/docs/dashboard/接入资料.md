## 1. 拓扑（重要：必须加一层本地代理）

```
浏览器（:8765 页面）
   │  fetch /api/...   ← 同源，无 CORS 问题
   ▼
本地小代理（建议挂在 :8765 同一服务，或 :3351）
   │  注入 Authorization: Bearer <本人密钥>
   ▼
中台 http://127.0.0.1:3350
```

**为什么必须代理：**
- 中台**不发 CORS 头**，浏览器直接 fetch `:3350` 会被拦。
- 本人密钥是全权密钥。**不能**放进浏览器 JS / localStorage。代理在服务端注入，浏览器永远见不到密钥。

**推荐代理形态**（Node，约 30 行，无依赖）：

```js
// proxy.mjs —— node proxy.mjs  (建议和界面同域，比如 :8765 的服务端加一条 /api 转发)
import { createServer } from 'node:http';
import { readFileSync } from 'node:fs';
const key = JSON.parse(readFileSync(process.env.HOME + '/.agent-autoloop/config.json', 'utf8')).owner;
const HUB = 'http://127.0.0.1:3350';
createServer(async (req, res) => {
  const url = new URL(req.url, HUB);
  if (!url.pathname.startsWith('/api/')) { /* 静态文件… */ return; }
  url.pathname = url.pathname.slice(4) || '/';
  const r = await fetch(HUB + url.pathname + url.search, {
    method: req.method,
    headers: { authorization: `Bearer ${key}`, 'content-type': req.headers['content-type'] ?? 'application/json' },
    body: ['GET', 'HEAD'].includes(req.method) ? undefined : req,
    duplex: 'half',
  });
  res.writeHead(r.status, Object.fromEntries(r.headers));
  if (r.body) await r.body.pipeTo(new WritableStream({ write: c => res.write(c), close: () => res.end() }));
  else res.end();
}).listen(3351);
```

注意：`/api/v1/stream` 是长连接（SSE）。上面的流式透传可以直接用；如现用 Python 静态服务器（`python -m http.server`），它不支持转发，需要换成 Node/带转发的服务器，或另起 `:3351` 代理并在页面里把 API 基址指过去（那样需给 `:8765` 页面对 `:3351` 开 CORS，仅限 `127.0.0.1`）。

**下文所有接口都写成 `/api/...`（代理前缀）；直连中台时去掉 `/api`，并自行带鉴权头。**

## 3. 接口全清单

### 3.1 探活

```
GET /api/healthz
→ 200 { "ok": true, "commit": "c9ec4a187cab49627947e7e33db265ec143db3b8" }
```
不需要密钥。`commit` 是中台运行版本。界面右上角「中台在线」状态灯用它。

### 3.2 全量快照（界面的主数据源）

```
GET /api/v1/state
GET /api/v1/state?before=<seq>     ← 历史轮次分页，每页 60 条 runs
```

一次返回**同一时刻的完整快照**（原子读出，不会撕裂）。顶层字段：

| 字段 | 含义 |
|---|---|
| `seq` | 快照对应日志序号。**实时流从这里接着读** |
| `now` / `timezone` | 中台时间与时区（本机时区） |
| `spending` | `{ today: {rounds, tokens, cached, cost…}, week: {...} }` 用量 |
| `totals` | `{ running, queued, retrying, unknown, done, doneToday, nothing, attention, usage }` 总览 |
| `cards` | **待拍板的卡片**（开着的） |
| `recentCards` | 最近卡片（含已关），每张多 `lane`（所属事项）、`about`（留给后续轮的说明） |
| `timers` | 定时器 |
| `sources` | 事件来源 |
| `lines` | **规则列表 = 界面左侧「项目/别墅」**，见下 |
| `pauses` | 生效中的暂停（每项带规则名 `name`） |
| `skipped` | 因暂停被跳过的事件（最近 20 条） |
| `agents` | **Agent 列表 = 界面右侧「塔」** |
| `channels` | 通道（如 desktop、飞书） |
| `runs` | **轮次列表 = 传送带上的「包裹」**，`?before=` 翻页 |
| `elsewhere` | 不在本机跑的事项 |
| `unrouted` | 没有规则接的事件 |
| `nextBefore` / `hasMore` | runs 翻页游标 / 是否还有更旧的 |

### 3.3 实时流（SSE）

```
GET /api/v1/stream?after=<seq>
```

- **先取 `/v1/state` 拿 `seq`，再 `after=<seq>` 接流，不漏不重。**
- 格式：SSE。每条 `id` = 日志序号，`event: fact`，`data` = 事实 JSON。
- 断线重连：带 `Last-Event-ID: <最后收到的 id>` 头，或 `?after=<同值>`，从下一条继续。
- `after=0` 读全量历史。按订阅速度逐条发送，不预缓存。
- 事实类型（节选）：轮次开跑/结束、卡片创建/回答、规则暂停/恢复/补跑/手动运行、用量更新。界面可按事实刷新 `state`，或只做轻更新（如流上来一条 run 结束就地更新包裹状态）。

### 3.4 为什么这轮做了这些（时间线）

```
GET /api/v1/runs/<id>/why
```
返回本轮的事实时间线：事件、每次执行的规则版本、领取、回执、卡片回答、接续轮次。界面「包裹详情 → 为什么」用它。

### 3.5 操作接口（写）

全部 `POST`，`Content-Type: application/json`。

**停一轮（停止包裹）：**
```
POST /api/v1/runs/<id>/cancel
→ 200 …
```

**回答卡片（拍板）：**
```
POST /api/v1/cards/<id>/answer   { "choice": 1 }          ← 选第 N 项（下标从 0 起）
POST /api/v1/cards/<id>/answer   { "text": "别的想法" }    ← 自由文字
```
- **只有第一次算数。** 后续回答会被拒——界面提交后立刻把卡片置灰。
- 通知类卡片的「已处理」按钮 = `answer` 带 `text`（处理说明），结案后存进 `answer` 字段。

**结案卡片（不决定了）：**
```
POST /api/v1/cards/<id>/resolve  { "reason": "不用决定了，因为……" }
```

**规则控制**（`<name>` 是规则名，中文名要 URL 编码）：
```
POST /api/v1/rules/<name>/pause    { "reason": "下游在修", "until": "2026-11-07T09:00:00+08:00" }
→ 200 { "changed": true, "rule": "…", "paused": { "by","reason","since","until","skipped" }, ... }

POST /api/v1/rules/<name>/resume   {}
→ 200 { "changed": true, ... , "paused": {…刚解除的这次暂停…, "skipped": { "count": N, "events": [最近20条] } } }

POST /api/v1/rules/<name>/replay   { "since": "2026-11-06T08:59:12.345Z" }
→ 200 补跑结果。`since` 必填、带时区。暂停中的规则 409「先恢复再补跑」；定时规则 400。

POST /api/v1/rules/<name>/run      { "subject": "#12", "reason": "看一眼" }
→ 200 { "event": 88, "run": 41 }   两项都可不写。暂停中的规则 409「先恢复再手动运行」。
```

**操作语义（界面要做对应处理）：**
- `pause` / `resume` / `replay` / `run` 是日志里的**事实**，不改配置文件，重启后依然有效。
- `until` 到点中台**自动恢复**。重复暂停只更新 `reason`/`until`，`since` 保留第一次。
- **暂停期间**：定时规则到点直接跳过（`lines[].skippedAt` 记最近跳过时刻，**不补跑**）；事件规则的事件照记但不派活，列在 `skipped`，要不要补由你决定（`replay`）。
- `run`（立即运行）走正常派活，`runs[].manual` 为 `true`。同事项已有排队轮次时并进去。
- 错误码：参数错 `400`，密钥错 `401`/`403`，不存在 `404`，暂停中想 run/replay `409`。

| 「模拟数据」角标 | `<span class="demo">模拟数据</span>` | 接真数据后**删掉** |

| —（缺）规则暂停/恢复 | 无 | `lines[].paused` 显示暂停徽标，按钮走 3.5 |

## 6. 语义与坑（必读）

1. **seq 契约**：`/v1/state` 的 `seq` 与 `/v1/stream?after=` 配合保证不漏不重。断线重连永远从最后收到的 `id` 续。不要用「每隔几秒轮询 state」代替流——能用，但会漏掉两次轮询之间的短暂卡片。
2. **只有第一次回答算数**：卡片 `answer` 提交后立刻置灰，别让人连点。
3. **暂停 ≠ 停止**：暂停中的规则**手动运行也一律 409**。这是设计使然（保证「暂停=不再花钱、不再对外动作」无例外）。界面要在暂停状态下禁用「立即运行/补跑」按钮，并提示先恢复。
4. **暂停期间漏掉的活**：定时规则错过的时刻**永久跳过**（`skippedAt` 只作记录）；事件规则的事件进 `skipped`，恢复后**不自动补**，要用 `replay`（`since` = 这次暂停的 `since`）手动补。`resume` 的应答里就带 `paused.skipped`，界面可直接给「补跑这些」按钮。
5. **`until` 自动恢复**：没人看应答。界面用流上的 `resumeRule` 事实刷新徽标。
6. **run 翻页**：`/v1/state` 只带最近一页 runs（60 条）。更旧的用 `?before=<nextBefore>` 翻，`hasMore` 告诉你还有没有。
7. **中文规则名进 URL 要编码**：`POST /api/v1/rules/${encodeURIComponent(name)}/run`。
8. **时间**：`now`/`timezone` 用中台的，显示相对时间（「12 分钟前」）比原始 ISO 友好。
9. **安全**：owner 密钥全权。代理只听 `127.0.0.1`，不要绑 `0.0.0.0`。
10. **幂等与并发**：操作接口按事实记账，重复点「立即运行」会真的多跑几轮——按钮提交后加短暂 loading 禁用。
